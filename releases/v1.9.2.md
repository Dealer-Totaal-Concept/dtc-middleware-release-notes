# DTC Middleware v1.9.2

**Release Date:** 2026-06-17T06:45:06Z

## Release Notes

## Release scope

  This release covers the production candidate from  onward. It is a small release focused on CK lead attribution, provider proxy
  and polling reliability, and release/CI tooling.

  ## Highlights

  - Added dealer and salesperson attribution to the CK create-lead flow, returned on funnel entry.
  - Hardened provider reliability by centralizing outbound proxy traffic with monthly usage monitoring and bounding poll-queue growth
  with shared back-off and retention.
  - Improved release and CI operations with merge-queue checks, a hotfix develop-sync PR flow, and safer Heroku release handling.
  - Fixed dealer-portal application status mapping and moved review queues to Redis Cloud.

  ## CK funnel and lease application

  - Accept dealer and salesperson ids on CK create-lead and return them on funnel entry. (#496)

  ## Providers, proxy, and polling reliability

  - Centralized the Fixie outbound proxy across providers and auth, and added monthly proxy-usage monitoring with a health route. (#467)
  - Bounded poll-queue growth with a shared back-off and retention utility, applied to BNP FL and Defam CK webhook polling. (#466)

  ## Dealer portal and queues

  - Updated application status mapping for the new HubSpot deal stage. (6f4c7ef)
  - Moved review queues to Redis Cloud. (#490)

  ## Release, CI/CD, and runtime

  - Prepared merge-queue checks in CI. (#495)
  - Added a workflow that opens a develop-sync PR for hotfix releases. (#488)
  - Ignored graceful Heroku process exits so they no longer fail releases. (#489)
